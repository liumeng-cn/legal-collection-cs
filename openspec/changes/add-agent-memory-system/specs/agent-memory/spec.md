## 新增需求

### 需求:记忆按用户隔离存储
系统必须将长期记忆按 `user_id` 隔离存储在 chat 库的 `user_memory` 表中，并将记忆区分为画像（`SEMANTIC`）与情节（`EPISODIC`）两类。情节记忆必须附带 `embedding` 向量以支持语义检索。

#### 场景:不同用户记忆隔离
- **当** 债务人 A 与债务人 B 分别产生长期记忆
- **那么** 系统按 `user_id` 分别存储，检索 A 的记忆时不得返回 B 的记忆

#### 场景:记忆类型区分
- **当** 写入一条用户偏好（画像）与一条还款承诺（情节）
- **那么** 系统分别以 `SEMANTIC` 与 `EPISODIC` 类型存储，情节附带 embedding 向量

### 需求:会话结束异步生成记忆
系统必须在会话结束后异步调用 LLM 摘要，抽取值得长期记住的画像与情节并写入 `user_memory`，且不得阻塞当前对话响应的返回。

#### 场景:会话结束触发摘要
- **当** 一次会话的最后一条回复流式完成
- **那么** 系统异步触发摘要任务，抽取用户画像与承诺并写入记忆表，当前响应已先返回用户

#### 场景:摘要失败不影响主流程
- **当** 摘要 LLM 调用失败
- **那么** 系统记录错误日志并放弃本次摘要，不得影响已返回的对话结果

### 需求:新会话加载记忆
系统必须在新会话开始时加载当前用户的记忆：画像全量注入 system prompt，情节按当前问题语义检索 top-k 后注入。

#### 场景:新会话注入记忆
- **当** 用户发起新会话的首条消息
- **那么** 系统检索该用户画像（全量）与情节（语义 top-k），注入 system prompt 后再进行推理

#### 场景:无记忆用户正常对话
- **当** 用户无任何历史记忆
- **那么** 系统跳过记忆注入，正常进入对话推理

### 需求:记忆更新覆盖旧记忆
系统必须在写入新记忆时，将与之冲突的旧记忆标记为 `SUPERSEDED`，禁止重复追加导致矛盾。

#### 场景:承诺改期覆盖旧承诺
- **当** 用户产生与原承诺冲突的新承诺（如原定 8/29 还款改期到 9/5）
- **那么** 新承诺写入，旧承诺标记为 `SUPERSEDED`，检索时不得同时返回相互矛盾的两条

### 需求:记忆衰减
系统必须通过后台异步批处理，将过时或已兑现的记忆标记为 `EXPIRED`，使其不再参与后续检索。

#### 场景:已兑现承诺失效
- **当** 后台批处理检测到承诺已兑现或长期未再提及
- **那么** 将对应记忆标记为 `EXPIRED`，后续检索不得返回该记忆
