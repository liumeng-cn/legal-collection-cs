## 新增需求

### 需求:会话历史跨轮加载
系统必须在每次交互时加载当前会话的历史消息，使多轮对话保持连贯，而非只携带最新一条消息。

#### 场景:多轮对话连贯
- **当** 用户在同一会话内发起后续提问
- **那么** 系统携带该会话的历史消息参与推理，使模型理解前文语境

### 需求:长对话自动压缩
系统必须在会话历史超过阈值时，自动将前缀消息压缩为一条摘要，保留最近若干条尾部消息，保证上下文有界且不无限增长。

#### 场景:上下文超阈值触发压缩
- **当** 会话消息条数或 token 估算超过配置阈值
- **那么** 系统将前缀压缩为摘要消息，保留最近若干条，继续推理

#### 场景:压缩前保留原始历史
- **当** 触发对话压缩
- **那么** 压缩前的原始消息另行保留（持久化），供事后审计或检索，不因压缩而丢失

### 需求:上下文溢出兜底
系统必须在模型因上下文超长报错时，强制执行一次压缩并重试，而非将错误直接抛给用户。

#### 场景:模型报上下文超长错误
- **当** 模型返回 `context_length_exceeded` 等上下文溢出错误
- **那么** 系统强制压缩对话历史后重试一次

#### 场景:未配置压缩时透传错误
- **当** 模型返回上下文溢出错误且系统未启用压缩
- **那么** 系统将错误按既有降级逻辑处理，不静默吞掉
